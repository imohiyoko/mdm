# 0012. iPhone・Mac の通知用の証明書を組織ごとに持つ

- 状態: 承認
- 日付: 2026-11-03
- 関連: [design.md](../design.md) 8.2、ADR 0007・0011

## 背景

Apple の MDM は、端末を起こす通知（APNs）に MDM の通知用の証明書を使う。これまではサーバーの設定に 1 つだけ書いていた。多くの組織で 1 台のサーバーを使うとき、Apple の決まりでは証明書は端末を使う組織の Apple ID で取るものであり、1 つの証明書をすべての組織で使うと、その Apple ID の持ち主が全組織の通知を握ることになる。証明書を取るには MDM の提供者（ベンダー）の署名が要り、組織の管理者が自分で用意するのは難しい。

## 決定

- 組織ごとに通知用の証明書を持てるようにする（`/v1/orgs/{id}/apple/push`）。無い組織はサーバーの設定の証明書を使う。設定の証明書は無くてもよい
- MDM が鍵と CSR を作り、鍵は外に出さない。サーバーにベンダーの証明書があれば、MDM が CSR に署名して Apple に上げるファイルまで作る。組織の管理者は Apple のサイトに上げて、返ってきた証明書を戻すだけにする
- 端末は登録のプロファイルの topic でしか通知を受けないので、登録した端末がある組織の topic は変えさせない。毎年の更新は同じ Apple ID で行う
- チェックインで端末の言う topic を組織のものと比べ、違えば断る

## 結果

- 組織ごとに自分の Apple ID で iPhone・Mac を管理できる。ほかの組織の証明書の期限切れや取り消しの影響を受けない
- ベンダーの証明書（Apple Developer Enterprise Program）を持つのはサーバーの運営者。持たない運営者のサーバーでは、組織は自分で取った証明書と鍵を入れる
- 通知用の証明書の鍵は保存先にそのまま持つ。漏れると通知を送れるが、命令そのものは端末の証明書で守られる
- ベンダーの署名のファイルの形は、公開されている実装に合わせた。Apple のサイトに実際に上げて確かめていない

## 検討した代替案

- 1 つの証明書をすべての組織で使う：設定は簡単だが、Apple の決まりと合わず、1 つの Apple ID にすべてが依存する
- 組織の管理者が証明書と鍵を必ず自分で用意する：ベンダーの署名を得る手段が組織に無いことが多い
