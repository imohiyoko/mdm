# 0015. ルーターとのあいだは RadSec（RADIUS over TLS）でも受け、ルーターは証明書で見分ける

- 状態: 承認
- 日付: 2026-11-03
- 関連: [design.md](../design.md) 7・8、ADR 0009・0010

## 背景

組織の管理者が自分のルーターを登録すると（ADR 0010）、ルーターは MDM にインターネット越しに問い合わせる。RADIUS（UDP）は MD5 と共有の秘密で一部の属性しか守らず、中身（端末の名前など）は見える。また、ルーターをインターネットのアドレスで見分けるので、家庭の回線のようにアドレスが変わる・ほかの家と共有される（CGNAT）ルーターは登録できなかった。

## 決定

- RadSec（RFC 6614、TCP の TLS）の待ち受けを足す（`radius.radsec_listen`）。中を流れる RADIUS の扱い（EAP-TLS・組織の制限・Message-Authenticator の確かめ）は UDP と同じ。共有の秘密は RFC のとおり `radsec`
- ルーターは MDM が発行したクライアント証明書で見分ける。発行する認証局は、端末の証明書の認証局（ネットワークの認証局）とは別の「RadSec のルーターの認証局」にする。ルーターの証明書で Wi-Fi に入ったり、端末の証明書でルーターのふりをしたりできない
- 組織の管理者は `POST /v1/orgs/{id}/radius-clients` に `"transport": "radsec"` で登録する。アドレスは要らない。MDM が鍵と証明書（3 年）を作り、登録のときだけ返す（秘密鍵は保存しない）。保存するのは証明書の指紋
- 接続ごと・要求ごとに、証明書の CN（ルーターの ID）と指紋が登録の一覧にあるかを確かめる。ルーターを消すとすぐに一覧を読み直すので、つないだままの接続でも次の要求から答えない
- MDM のサーバーの証明書は、端末が確かめるものと同じ RADIUS のサーバーの証明書（ネットワークの認証局が `server_name` に発行したもの）。ルーターはネットワークの認証局と `server_name` で MDM を確かめる

## 結果

- ルーターと MDM のあいだの通信がすべて暗号化され、ルーターのアドレスが変わっても使える
- 証明書を作り直すときは、ルーターを消して登録し直す（指紋が変わる）。期限の 3 年が来る前に登録し直す
- RadSec に対応したルーター・アクセスポイント（または radsecproxy などの中継）が要る。家庭用のルーターには無いことが多い
- RadSec の待ち受けは UDP の待ち受け（`radius.listen`）と一緒に使う（ルーターの一覧の読み直しを共有する）

## 検討した代替案

- 共有の秘密と、TLS のサーバー認証だけ（クライアント証明書なし）：秘密が漏れると誰でもルーターのふりができる。RFC 6614 も相互認証を求める
- ルーターの証明書をネットワークの認証局で発行：端末の証明書とルーターの証明書の区別が CN の形だけになり、取り違えると危ない
- DTLS（RFC 7360）：対応する機器が少ない
