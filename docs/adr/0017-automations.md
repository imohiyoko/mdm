# 0017. 自動のルールは「当たっているあいだ別のポリシーを使う」形にする

- 状態: 承認
- 日付: 2026-11-03
- 関連: [design.md](../design.md) 8.7、ADR 0008・0016

## 背景

管理者は「平日の夜は子どもに勉強用のルールを使わせる」「暗号化していない会社の端末は、直るまで社内のサイトだけにする」のような、条件で決まるルールを、毎回手で切り替えずに済ませたい。ルールの API（ADR 0016）で外の自動化からポリシーを書き換えることもできるが、それでは MDM が止まっていたり、外の仕組みが失敗したりすると、切り替えたまま戻らない。

## 決定

- 組織ごとの **自動のルール**（`core.Automation`）を置く。条件・対象・使うポリシーを持つ
  - 条件は 2 つ：**曜日と時間帯**（`schedule`。タイムゾーン付き）と、**準拠していない**（`noncompliant`。準拠しない理由のどれかがある）
  - 対象はグループ（持ち主がどれかに入っている端末）か、組織のすべての端末
  - 当たっているあいだ、端末は決めたポリシーを使う。外れると元のポリシーに戻る
- 何かを書き換えるのではなく、**判定のたびに今の条件で決める**。ポリシーの決め方の先頭に「当たっている自動のルール」を足す（自動のルール → 端末 → 持ち主 → グループ → 組織の既定 → サーバー全体の既定）。止めていても、消しても、元に戻すための片付けが要らない
- 当たっているものが複数あれば、優先度の高いもの（同じなら ID の順）を使う。ほかの組織のポリシーを指していれば使わない
- **準拠の判定は元のポリシーの条件で行う**。切り替えたポリシーの条件で判定し直すと、準拠する → 戻る → 準拠しない、と行ったり来たりするため
- 通信フィルターは問い合わせごとに今の時刻で決めるので、すぐに切り替わる。MDM で配るもの（Android・iPhone・Mac）は、自動のルールが効いている端末が変わったのを 30 秒ごとに見て配り直す。Windows は端末が取りに来るときに配る
- 使われているポリシーとグループは消せない（409）。組織ごとに 50 まで
- 管理の API（`/v1/automations`）と管理画面の「自動のルール」で作る・止める・消す。操作は記録に残る

## 結果

- 「ルールベースで自動にルールを変える」ことが、MDM の中だけで閉じてできる。外の自動化（ルールの API）は、ポリシーそのものを変えるのに使う
- 準拠していない端末を絞る使い方は、IAM への知らせ（ADR 0008）と別に、端末そのものの通信を絞れる
- MDM で配る端末では、切り替えが端末に届くまで、配り直しの間隔と端末の通信の分だけ遅れる

## 検討した代替案

- 条件に当たったら、ポリシーや端末の設定を書き換える（イベントで動く）：戻し忘れ・二重の実行・MDM が止まっていたあいだの取りこぼしが起きる。元の値を覚えておく場所も要る
- 外の自動化（cron とルールの API）に任せる：MDM の中で閉じず、失敗したときに切り替えたまま戻らない
- ポリシーに時間帯ごとの中身を持たせる：止める時間帯（quiet hours）はすでにあるが、ルール全体（アプリ・端末の制限）を時間帯で変えるには、ポリシーの形が大きくなりすぎる
