# 0010. 組織の管理者がルーターと IAM の受け手を API で登録する

- 状態: 承認
- 日付: 2026-11-03
- 関連: [design.md](../design.md) 8、ADR 0004・0008・0009

## 背景

MDM を多くの組織（家族・会社）向けのサービス（SaaS）として動かしたい。これまで Wi-Fi のルーターと準拠の知らせの受け手（IAM）はサーバーの設定ファイルにしか書けず、組織の管理者は自分で設定できなかった。組織の管理者に開くと、ほかの組織に影響する設定や、サーバーの内側に届く設定ができてしまう。

## 決定

- 組織の管理者は、自分の組織のルーターと受け手を管理の API で登録する。登録したものは、その組織の端末にだけ効く
- ルーターのアドレスはインターネットのもので、狭い範囲だけ。ほかの登録・設定と重なるものは断る。RADIUS はアドレスでルーターを選ぶので、重なりを許すとほかの組織のルーターの問い合わせを奪えるため
- 共有の秘密は MDM が作る（推測できる短い秘密を使わせない）。RADIUS の確かめに元の値が要るので、保存先にそのまま持つ
- 受け手は https の URL だけで、送るときにつなぐ先のアドレスを確かめる。名前を引いた結果で確かめないと、DNS で内側のアドレスを返されたときに防げない
- 設定ファイルのルーター・受け手は残す。家の中のアドレスや社内の IAM など、サーバーの管理者が信じて置くもの

## 結果

- サーバーの管理者を通さずに、組織ごとに Wi-Fi と IAM の連携を始められる
- ルーターは MDM にインターネット越しに問い合わせることになる。RADIUS（UDP）は中身の一部しか守られないので、RadSec（RADIUS over TLS、RFC 6614）を後で足す（ADR 0015 で足した）
- 保存先が漏れると、ルーターの共有の秘密と受け手の Bearer の値が漏れる

## 検討した代替案

- 組織ごとに RADIUS のポートを分ける：ルーターの設定は簡単になるが、組織の数だけポートが要る
- 受け手の URL の名前を登録のときに引いて確かめる：あとで DNS を変えられると防げない
