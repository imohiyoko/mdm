# 0006. Windows は合言葉で登録し、端末の証明書で確かめる

- 状態: 承認
- 日付: 2026-11-03
- 関連: [design.md](../design.md) 5.2、ADR [0003](0003-platform-channels.md)

## 背景

Windows は標準の MDM（登録は MS-MDE2、管理は OMA-DM）で管理する（ADR 0003）。登録には利用者の確かめ方を選ぶ必要があり、管理の通信では端末を確かめる必要がある。家庭では Microsoft Entra ID（会社のアカウント）を使わないことが多い。

## 決定

- 登録の確かめ方は OnPremise（メールアドレスとパスワード）にする。パスワードには、管理者が端末ごとに作る 1 回だけの合言葉（15 文字、75 ビット、既定 24 時間）を使う。メールアドレスは何でもよい
- 登録で、MDM の認証局が端末の証明書（CN は MDM の端末の ID、5 年）を発行する。管理の通信はその証明書（TLS のクライアント証明書）で端末を確かめ、MDM が覚えている証明書の SHA-256 と一致するものだけを受け付ける
- 認証局の証明書は端末の信頼する証明書に入るので、用途をクライアント認証だけに絞る（鍵が漏れても、サーバーのなりすましには使えない）
- 端末の証明書を受け取るため、Windows の入り口はリバースプロキシを通さず、MDM が直接 TLS を受ける（`windows.listen`）
- 端末は決まった間隔（既定 15 分）で通信してくる。命令は待ち行列に入れ、そのときに渡す。答えの無い命令は 30 分後に送り直す。プッシュ（WNS）は後で足す
- ポリシーは毎回すべての値を書き（前の値を消すため）、要約が変わったときだけ配る
- 証明書の自動の更新はまだしない（期限の前に登録し直す）

## 結果

- Entra ID が無くても、家庭の Windows（Home を含む）を登録できる
- 命令（再起動・初期化）が届くまで、最大で通信の間隔だけかかる
- Windows では通信フィルターをまだ端末に固定できない（手で設定する）
- Microsoft Store のアプリの禁止は AppLocker を使う。Windows の版によっては効かない（Enterprise・Education で確実）

## 検討した代替案

- Federated（ブラウザーでログインする登録の画面）：IAM でログインさせられるが、登録の画面と仕組みが増える。会社向けに後で足す
- 通信の中のダイジェスト認証（syncml:auth-md5）で端末を確かめる：リバースプロキシの後ろに置けるが、MD5 に頼る
- 証明書をリバースプロキシで受けてヘッダーで渡す：設定の誤りでなりすましができてしまう
