# 0008. 端末の準拠はポリシーの条件で判定し、変化を SSF で iam に知らせる

- 状態: 承認
- 日付: 2026-11-03
- 関連: [design.md](../design.md) 6.1、iam の ADR 0118（Shared Signals Framework）

## 背景

会社のエンドポイント管理では、ルールに沿っていない端末（暗号化していない、OS が古いなど）を仕事に使わせたくない。判定は端末の情報を持つ MDM がし、ログインを止めるかは iam が決める。iam は OpenID Shared Signals Framework（SSF）の受信側を持ち、CAEP の `device-compliance-change` を受けて端末の準拠の状態を記録する（iam の ADR 0118）。

## 決定

- 準拠の条件はポリシーの `compliance` に置く（端末 → 人 → グループ → 組織 → 全体の順で決まる、ほかのルールと同じ）。MDM で管理していることと、ポリシーを受け入れていることはいつも求め、暗号化・画面ロック・OS の最低の版・報告の途切れは選べる
- 判定は決まった間隔ですべての端末について行い、結果を置く。機種ごとの管理の仕組み（Android・Windows・Apple）は今の `core.Managed` を書くだけで、判定を知らなくてよい
- 知らせは SSF の送信側として、準拠しているかが変わったときだけ、push（RFC 8935）で送る。SET は ES256 で署名し、公開鍵を `public.base_url` の `/.well-known/jwks.json` に出す。iss は `public.base_url`
- 利用者は持ち主のメールアドレス（iam で確認済みのもの）で示す。iam の受信側が `email` で利用者を引くため。端末は MDM の端末の ID（不透明な値）で示す
- 送る待ちは保存先に置き（outbox）、送れなければ送り直す。受け手が 400 で断ったもの（RFC 8935 2.3）は送り直さない
- iam のストリームの管理 API（受信側がストリームを作る形）は持たない。iam の受信側は、送信側の受け口の登録と push の Bearer の値で受ける

## 結果

- iam は端末の状態を待たずに知れる。判定に使う形は iam の側で決める
- 持ち主のいない端末・メールアドレスの無い人の端末は知らせない（判定の結果は MDM で見られる）
- 間隔のあいだの変化は次の判定まで遅れる（既定 1 分）
- 判定の材料は機種ごとの管理の仕組みが取り込んだ値なので、取り込みの間隔（Android 5 分、Windows 15 分、Apple 6 時間）だけ古いことがある

## 検討した代替案

- iam のイントロスペクションのたびに MDM に問い合わせてもらう：iam が MDM に依存し、ログインのたびに通信が増える
- 機種ごとの管理の仕組みで判定する：条件が機種ごとにばらける。`core.Managed` にそろえてあるので 1 か所で判定できる
- Webhook で独自の形を送る：iam が受けるのは SSF なので、標準の形にする
