# 0011. IAM でログインした人が自分で組織を作り、招待のコードで管理者を足す

- 状態: 承認
- 日付: 2026-11-03
- 関連: [design.md](../design.md) 8.1、ADR 0004・0010

## 背景

MDM を多くの組織向けのサービス（SaaS）として動かすには、新しい組織が来るたびにサーバーの管理者が組織を作り、IAM のユーザーの id（`sub`）を調べて役割を与えるのでは回らない。組織の管理者がほかの管理者を足すときも、相手の `sub` を知る手段が無い。

## 決定

- 設定の `signup.enabled` があれば、IAM でログインした人は自分で組織を作り、その組織の `org_admin` になる。組織・役割・作った記録は 1 つのトランザクションで入れる
- 1 人が自分で作れる組織の数に上限を置く（既定 3）。数は作った記録で数え、招待で入った組織や、消した組織は数えない
- IAM でログインできて役割の無い人に開くのは、自分を見る・組織を作る・招待を受けるの 3 つだけ。ほかの API は今までどおり 401。役割の無い人を一般の API に通すと、サーバー全体のもの（組織の無いポリシーなど）を「誰でも見られる」と扱うところから漏れるため、入り口で絞る
- 管理者を足すのは招待のコードで行う。コードを持つ人なら誰でも受けられる（持参人の方式）。メールアドレスで縛ると、IAM のメールアドレスが確かめられているかを MDM が知れないため。コードは乱数 32 バイトで、保存は SHA-256 だけ、7 日で切れ、1 回で消える
- 招待で与えられるのは `org_admin` と `org_viewer` だけ。サーバー全体の管理者にはできない

## 結果

- サーバーの管理者を通さずに、組織の作成から管理者の追加までできる
- コードが漏れると、受けられる前なら誰でもその組織の管理者になれる。本人にだけ渡し、受けられたかは招待の一覧（受けたら消える）と操作の記録（`invitation.accept`）で確かめる
- サインアップを開いた IAM に誰でも登録できるなら、誰でも組織を作れる。組織ごとの使える量の上限は 8c で足す
- 組織の管理者は自分の組織のほかの管理者（作った人も）を外せる。最後の管理者を外したら、サーバーの管理者が戻す

## 検討した代替案

- 招待をメールアドレスで縛る：IAM の `email_verified` を MDM が受け取れるようになったら、縛る方式を足せる
- 役割の無い人も一般の API に通し、各 API で断る：断り忘れが漏れになる
