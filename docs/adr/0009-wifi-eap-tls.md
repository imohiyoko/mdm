# 0009. 証明書で Wi-Fi に入る仕組み（EAP-TLS）の RADIUS を MDM に持つ

- 状態: 承認
- 日付: 2026-11-03
- 関連: [design.md](../design.md) 7

## 背景

家や会社の Wi-Fi に、管理している端末だけを入れたい。合言葉（WPA2・WPA3 Personal）は端末から読み出せて人に教えられるので、知っている人は誰でも入れる。WPA2・WPA3 Enterprise にすると、ルーターは RADIUS のサーバーに認証を任せる。端末の証明書で入る EAP-TLS なら、合言葉が無く、端末ごとに止められる。

FreeRADIUS などを別に動かすこともできるが、証明書の発行・止める一覧・準拠の状態を MDM と同期する仕組みが要り、家庭で使うには準備が多い。

## 決定

- MDM が RADIUS のサーバー（EAP-TLS だけ）を持つ。証明書の発行と止めることは MDM の保存先だけで決まる
- ネットワークの認証局を、Windows・Apple の端末の認証局とは別に持つ。端末がサーバーを確かめるのに使うので、サーバーの名前を `radius.server_name` だけに名前の制約で絞る
- 端末の証明書は MDM が鍵ごと作り、PKCS#12 で返す（Windows・Apple の配布で、そのまま端末に入れられる形）。保存するのは指紋だけ
- 入れるのは、覚えている指紋の証明書だけ（止める一覧ではなく、許す一覧）。選べば準拠も求める
- Message-Authenticator をいつも求める（BlastRADIUS、CVE-2024-3596）。RADIUS の通信自体は暗号化されないので、ルーターと MDM は同じ家・会社の中の回線でつなぐ
- TLS 1.2 では Extended Master Secret を求める。Go の TLS は EMS が無いと鍵を取り出せないため。Windows 10 以降・iOS・macOS・Android・wpa_supplicant は EMS を使う

## 結果

- ルーターの設定は「WPA2・WPA3 Enterprise、RADIUS のサーバーの IP、ポート 1812、共有の秘密」だけでよい
- 端末への配布（Wi-Fi の設定・証明書・認証局）は MDM の機種ごとの仕組みで後から行う（段階 7b-2）。Android は Android Management API で証明書を入れられないので、手で入れるか、後で考える
- 認証は端末の証明書だけで、人（利用者）の確かめはしない。端末の持ち主はポリシーで決まる
- 1 台の RADIUS で受ける。止まると Wi-Fi に新しく入れない（入っている端末はつながったまま）

## 追記：MDM での配布（段階 7b-2）

- 配る Wi-Fi はポリシーの `wifi` に書く（家と会社で分けられる）。端末の証明書は配るたびに MDM が作り、鍵は命令の中にだけ置いて、端末の答えを受けたら消す
- 前の証明書は、端末が新しいものを受け取ってから取り消す。受け取る前に取り消すと、その Wi-Fi でしかつながらない端末が新しいものを取りに来られない

## 検討した代替案

- FreeRADIUS を別に動かす：同期の仕組みと準備が増える。大きな会社では今後これを使える形（認証局を渡す）も考える
- PEAP・EAP-TTLS（ID と合言葉）：合言葉が漏れる問題が残る。古い MSCHAPv2 を使うものが多い
- Windows・Apple の端末の認証局を使う：用途がクライアント認証だけで、サーバーの証明書を発行できない。端末に信頼させるとほかの用途に広がる
