# 0004. 組織で分け、管理者は iam でログインする

- 状態: 承認
- 日付: 2026-11-03
- 関連: [design.md](../design.md) 3.5、3.6

## 背景

家庭の見守りだけでなく、会社のエンドポイント管理にも使う。会社では部署ごとにルールを変え、管理者を役割で分け、管理者のログインを会社の IdP にそろえたい。1 つのサーバーで複数の家族・会社を管理することもある。

## 決定

- 組織（家族・会社）を管理の単位にし、人・グループ・端末・ポリシーをどれか 1 つの組織に属させる。組織をまたいで指せない
- グループは人のまとまり（部署など）。人は複数のグループに入れ、ポリシーは優先度の大きいグループのものを使う
- 管理者の役割は `server_admin`・`org_admin`・`org_viewer` の 3 つ。細かい権限（グループごとの管理者など）は、要る場面が出てから足す
- 人の管理者は iam でログインする。MDM は iam の連携先としてアクセストークンをイントロスペクションで確かめ、役割は MDM が持つ（iam の `iss` と `sub` に結び付ける）
- 設定の鍵は残す（最初の管理者の登録、自動化）

## 結果

- 1 つのサーバーで複数の家族・会社を分けて管理できる
- 役割を iam のロールではなく MDM が持つので、iam の設定を変えずに管理者を足せる。iam でユーザーを止めればログインできなくなる
- イントロスペクションの答えを 30 秒まで覚えるので、失効の反映がその分遅れる
- 管理画面（段階 8）はブラウザで iam の認可コードフローを使い、同じアクセストークンで API を呼ぶ

## 検討した代替案

- 役割を iam のロール（クレーム）で持つ（iam の不透明トークンではクレームが届かず、イントロスペクションの答えに頼ることになる。組織の ID を iam と MDM でそろえる手間もある）
- 組織を分けず、1 サーバー 1 組織にする（家族と会社を 1 台で扱えない）
