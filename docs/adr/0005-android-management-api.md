# 0005. Android は端末ごとに AMAPI のポリシーを作り、DNS のホスト名は登録のときだけ配る

- 状態: 承認
- 日付: 2026-11-03
- 関連: [design.md](../design.md) 5.1、ADR [0002](0002-dns-filter-per-device.md)、[0003](0003-platform-channels.md)

## 背景

Android は Google の Android Management API（AMAPI）で管理する（ADR 0003）。通信フィルターを端末に固定するには、端末の Private DNS（DoT）を端末ごとのホスト名 `{ラベル}.{domain}` に設定する必要がある。サーバーはラベルの SHA-256 しか持たない（ADR 0002）。

## 決定

- 組織ごとに Google の enterprise を 1 つ作る。作る画面（signup URL）から戻ってくる URL には 1 回だけ使える秘密（1 時間で期限切れ）を付け、組織と結びつける
- AMAPI のポリシーは端末ごとに 1 つ作る（名前は MDM の端末の ID）。ホスト名を端末ごとに変えるため
- ホスト名（`deviceConnectivityManagement.privateDnsSettings`）は、登録のときと DoT のラベルを作り直したときだけ、新しいラベルの平文から作って配る。ふだんの配り直しは `updateMask` で MDM の受け持つ項目だけを変え、ホスト名には触らない。サーバーにラベルの平文を残さないため
- 登録の鍵は 1 回だけ使え、`additionalData` に MDM の端末の ID を入れる。端末の取り込みは、MDM が付けたポリシーの名前で結びつける
- 端末の状態は一定の間隔（既定 5 分）で一覧を取り込む。Pub/Sub の通知は後で足す
- 管理している端末は消せない・OS を変えられない（先に管理を外す）。完全管理の端末は管理を外すと初期化されるので、`confirm_wipe` を要る

## 結果

- 端末ごとにポリシーがあるので、AMAPI の呼び出しは端末の数だけ増える。ポリシーの要約（ハッシュ）を覚え、変わった端末にだけ配る
- 通信フィルターを端末に固定できるのは完全管理の端末だけ（AMAPI の制約）。私物の仕事用プロファイルでは、利用者が手で設定する
- ラベルを作り直して配れなかったときは、端末の通信が止まらないように元のラベルに戻す

## 検討した代替案

- ポリシーを MDM のポリシーごとに 1 つにする（呼び出しは減るが、端末ごとのホスト名を配れない）
- ラベルの平文を保存する（データベースが漏れると、他人がその端末として DNS を使い、記録を汚せる）
- ラベルを鍵から計算する（HMAC。設定に鍵が 1 つ増え、鍵を変えると全端末のホスト名が変わる）
